### `dsh-service-hub` / `local-service-hub` 的确切故障

- `service-hub/hub.py` 三处按固定文件名扫描会话：`rglob("session.jsonl.zstd")`（第 292 / 798 / 847 行）。
- `0.1.2-alpha.5` 落盘名：`sessions/<ws>/<sessionId>/session.jsonl.zstd`
- `dsh-v0.1.5-rc.2` 落盘名：`sessions/<ws>/<sessionId>/session.v3.jsonl.zstd`（带版本号）
- 实跑对照：8893 的 DSH_HOME 下**确实存在**一个 22KB 的 `session.v3.jsonl.zstd`；向常驻服务台请求 `/api/usage?refresh=1`，服务台共扫到 **211 个会话，来自 8893 的为 0 个**（按 cwd 归类同样为 0）。
- 影响：服务台的「按会话对话输入统计」以及所有依赖会话日志的页面在新版本上静默为空。
- 修复方向：把 glob 放宽为 `session*.jsonl.zstd`（并兼容解压多帧 zstd），改动量约 3 行。

## 六、本地补丁在新版本上的存亡（重点）

`deploy/omgwow-dsh` 唯一的核心代码修改是 `packages/llm/llm-pi-ai` 的 `mergeUserMessages`（修复 Token Router 腾讯链路在合并连续 user 消息时丢图，导致 gpt-5.6-sol / kimi-k3 读图失败）。

- 在 `dsh-v0.1.5-rc.2` 全树检索 `mergeUserMessages` 与 `mergeConsecutiveUserMessages`：**命中 0 次**。上游没有以别的名字吸收这个能力。
- profile 里 `mergeUserMessages: true` 仍然写着：新版 `llm-pi-ai` 的 profile schema 里没有这个键，且它的 `rejectRemovedFields()` 只对 `provider` / `maxRetries` / `maxRetryDelayMs` 报错——**这个键既不生效也不报错，属静默失效**（8893 能正常启动、正常出话，正是因为它被无声忽略）。
- 结论：**升级必须重新应用该补丁**，否则 gpt-5.6-sol / kimi-k3 的读图链路会退回修复前的行为。

  `const history = mergeUserMessages === true ? mergeConsecutiveUserMessages(split.messages) : split.messages`
