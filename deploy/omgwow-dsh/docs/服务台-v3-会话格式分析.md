# dsh-service-hub / local-service-hub 在 0.1.5 上的失效分析

> 结论先说：**组件没坏，插件没坏，坏的是一行文件名匹配。** 会话日志在新版本里换了名字，
> 服务台按旧名字找不到它们，于是"什么都没找到"——不报错、不崩溃，只是安静地显示为空。

---

## 1. 这个组件由哪几部分组成

| 部分 | 位置 | 职责 |
|---|---|---|
| 自研插件 `dsh-service-hub` | `plugins/dsh-service-hub/` | 把当前 dsh 实例（id / base_url / dsh_home）注册进常驻服务台；渲染侧边栏入口 |
| 常驻服务台进程 | `/Users/lbc/Documents/dsh-v2/service-hub/hub.py`（127.0.0.1:6692） | 单文件 Python：实例表、服务表、会话输入统计、集群任务、页面 |
| skill `local-service-hub` | `dsh-home/skills/local-service-hub/` | 让 agent 遵守"起本地服务要登记到服务台"的约定 |

三者协作：插件登记实例 → 服务台按实例的 `dsh_home` **扫描会话日志** → 生成
"按会话的对话输入统计"等页面。

## 2. 症状

| 现象 | 实测 |
|---|---|
| 新版实例本身注册正常 | `/api/instances` 能看到 `8893 / dsh-v2-015 / .../instance-015/dsh-home` |
| 服务台在跑、接口正常 | `/api/health` 返回 ok |
| **会话统计里没有新实例的任何会话** | `/api/usage?refresh=1`：共 211 条会话，属于新实例的 **0 条** |
| 磁盘上明明有会话 | 新实例 DSH_HOME 下确有一个 22KB 的 `session.v3.jsonl.zstd` |

关键点：**没有报错**。服务台扫描的是一批路径，匹配不到就是空集合，因此表现为"静默为空"，
而不是崩溃——这也是它容易被误判成"插件坏了"的原因。

## 3. 根因：会话日志文件名带上了格式版本号

`hub.py` 有三处按**固定文件名**扫描：

```python
root.rglob("session.jsonl.zstd")   # 第 292 / 798 / 847 行
```

而两代 dsh 的落盘名字不同：

| dsh 版本 | 落盘文件名 |
|---|---|
| `0.1.2-alpha.5`（现 8892 实例） | `sessions/<ws>/<sessionId>/session.jsonl.zstd` |
| `dsh-v0.1.5-rc.2`（新 8893 实例） | `sessions/<ws>/<sessionId>/session.v3.jsonl.zstd` |

0.1.5 把会话格式版本从 v1 升到 **v3**，并把它**内嵌进文件名**。固定名 glob 因此
对新版本 100% 失配。

## 4. 为什么"只修 glob"就够了：解析逻辑其实完全兼容

我解压了真实的 v3 日志逐条核对，服务台依赖的三类记录在 v3 里字段没变：

```json
{"type":"session","version":3,"id":"session-4e91eca1-…","createdAt":…,"cwd":"/tmp/ws-015",…}
{"type":"user/message","seq":8,"time":…,"data":{"content":[{"type":"text","text":"…"}],
 "source":{"kind":"user","rpcId":"…"},"role":"user","id":"…"},"surfaceOp":"append"}
```

- `session` 记录：`id` / `cwd` / `createdAt` 仍在 → 会话身份与工作区可解析
- `session/title` 记录：`data.title` 仍在 → 标题可解析
- `user/message` 记录：`data.content[].text` 与 `data.source.kind` 仍在
  → "只统计真实用户输入"这条规则（`kind == 'user'`，排除 plugin / skill-catalog /
  subagent 等注入）照旧成立

所以**解析代码、过滤规则、统计口径都不需要动**，改动面就是"怎么找到这些文件"。

## 5. 修复

在 `hub.py` 里把三处固定名 glob 收敛成一个按名精确匹配的辅助函数：

```python
# 0.1.2-alpha.5 为 session.jsonl.zstd；0.1.5 起变成 session.v3.jsonl.zstd。
_SESSION_LOG_NAME = re.compile(r"^session(?:\.v\d+)?\.jsonl\.zstd$")

def _session_logs(root: Path) -> list[Path]:
    """列出某个配置区下所有 dsh 会话日志（兼容各代落盘文件名）。"""
    try:
        candidates = list(root.rglob("session*.jsonl.zstd"))
    except OSError:
        return []
    return [path for path in candidates if _SESSION_LOG_NAME.fullmatch(path.name)]
```

三处调用改为 `_session_logs(root)`（其中一处保留 `sorted(...)`）。

选择按名字精确匹配而不是直接 `rglob("session*.jsonl.zstd")`，是为了不误收
`session-backup.jsonl.zstd` 这类同前缀文件；这个正则同时覆盖 v4/v5 之后的命名，
下一轮升级不会再因此失效。

**部署范围**：改了实例内副本，**并同步部署到常驻服务台**（`/Users/lbc/Documents/dsh-v2/service-hub/hub.py`，
旧文件已备份为 `hub.py.bak-pre-v3-glob-<时间戳>`），随后重启了该进程。

## 6. 验证（同一查询前后对比）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `refresh=1` 扫到的会话总数 | 211 | **217** |
| 其中属于新实例 | **0** | **6** |
| 与磁盘文件对应 | — | 6 个文件 ↔ 6 条记录，一一对应 |
| 标题解析 | — | 全部正确（"列出名称含present等关键词的工具"…） |
| 输入统计数值 | — | 逐条核对，字符数与实际提问一致（如 32、25 字符） |

最后一项尤其关键：它证明链路不是"找到了文件"，而是**发现 → 解压 → 解析 → 按
`source.kind=='user'` 过滤 → 计数**整条都通。

## 7. 影响面与建议

- 受影响功能：服务台的**会话列表、按会话的对话输入统计、会话→集群任务关联、
  会话→服务页面关联**（凡是经 `_scan_sessions()` / `_scan_roots()` 的都受影响）。
- 不受影响：实例登记、服务登记、集群总览（走 SQLite 与 K8s/SSH 轮询，不读会话日志）。
- 建议：升级任何实例前，把"会话日志文件名"当作**版本相关契约**看待；
  升级 8892 时同一份修好的 `hub.py` 直接复用（它同时兼容两代命名，无需按版本切换）。
