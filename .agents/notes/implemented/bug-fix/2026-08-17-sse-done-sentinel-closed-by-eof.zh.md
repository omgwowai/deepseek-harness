# Agent Note: 以 EOF 而非空行结束的 `[DONE]` 哨兵

Status: implemented

[English](2026-08-17-sse-done-sentinel-closed-by-eof.md) | 中文

## Problem

`parseSse` 按规范严格分派事件：`eventsource-parser` 只在看到终结事件的空行时才发出该事件，因此若某条流的最后几个字节是 `data: [DONE]\n`——只有一个换行、没有空行——哨兵就永远不会被产出。循环耗尽后，函数对一个提供方其实已经完整返回的响应抛出 `STREAM_CLOSED: SSE stream ended without [DONE]`。

某些 OpenAI 兼容网关会在哨兵行本身处关闭连接。在一条提供 `glm-5.3` 的网关路由上观察到：每一条响应都以 `…[DONE]\n` 结束，而同一网关的 DeepSeek 路由则以 `…[DONE]\n\n` 结束。该失败是必现而非偶发的——五次抓包五次如此，其中包括已携带完整工具调用与 `finish_reason: tool_calls` 的响应——因此尽管线路上的字节是完整的，该模型经由此适配器完全不可用。症状指向了传输层，却将其归因于截断，而截断恰恰是唯一没有发生的事。

原有行为是有意为之且有测试固定的（`treats a final DONE missing its blank-line terminator as truncation`），其前提是"真实的提供方总会终结事件"。上述观察证伪的正是这个前提。

## Decision

哨兵豁免空行终结要求，承载数据的事件不豁免。`parseSse` 保留最后一个完整事件终结符之后的文本；当生成器耗尽而未分派哨兵时，若该尾部文本恰好是一行 `data: [DONE]`（可带一个换行），则接受该流。其余情况仍抛出 `STREAM_CLOSED`。

这一豁免恰恰在它被应用之处是安全的。被 EOF 截断的数据事件与完整事件无法区分，这正是严格分帧必须继续守护它的原因。而哨兵不携带任何数据：它的全部内容就是终结标志，因此 EOF 若将其截短，必然留下一个匹配不上的尾部——`data: [DON` 与 `data: [DONE] extra` 都仍会抛错。于是流中有用部分的截断依然可被检出，该检查的目的得以保全。

`retainTail` 是位于解码器与解析器之间的透传 transform，而非第二次解析：`eventsource-parser` 会丢弃未终结的尾部，而只有原始解码文本才能说明 EOF 究竟是截断了某个事件，还是结束了哨兵行。按 SSE 语法允许的三种换行分别切分、并以最靠后的匹配为准，可使混用换行的流也能得到正确的尾部。

## Alternatives considered

**在 EOF 时冲刷解析器的待定缓冲。** 向 `eventsource-parser` 索取其持有的内容，并把待定的 `[DONE]` 视为已分派。之所以否决：该库并未暴露这样的冲刷接口；而在上游添加它，会对所有事件而非仅对哨兵放宽分帧——正是这一区分让本方案安全，通用冲刷恰好抹除了它。

**取消对 `[DONE]` 的要求。** 在 EOF 时正常返回，让调用方依据 `finish_reason` 判断完整性。之所以否决：这是对一个真实信号的真实损失。哨兵正是该适配器用以区分"响应已完成"与"连接在作答途中断开"的依据，而 `finish_reason` 恰恰在该检查所要捕捉的截断流中是缺失的。

**按模型或按网关处理。** 用一个配置项列出会在哨兵处关闭的端点，据此启用宽松模式。之所以否决：不能指望运维者了解其网关 SSE 写入端的分帧细节；失败信息也无从提示该把值设成什么；而宽松路径本就是无条件安全的——它是关于哨兵的事实，而非关于某个端点的事实。

**解析前规范化字节。** 当流末缺少空行时补上一个。之所以否决：这在范围上严格更宽——它会重新终结任何未终结的尾部，于是被 EOF 截断的数据事件也会被当作完整事件解析并交付，而这正是严格检查所要防止的失效模式。

## Testing

`tests/sse.spec.ts` 覆盖了接受的形态（无换行、单个 LF、单个 CRLF、字段名后无空格、哨兵为流中唯一事件、以及哨兵跨读切分）、混合换行下的尾部测量，以及拒绝的形态（被截断的数据载荷、只写了一半的哨兵、哨兵后还跟着其他未终结文本、哨兵之后又出现未终结事件）。`src/sse.ts` 的单文件覆盖率在语句、分支、函数、行四项上均为 100%。

已对真实网关做端到端验证：此前在工具调用中途以 `STREAM_CLOSED` 失败的 `glm-5.3` 会话，现已能完成"写入后读回"的完整工具循环；同一构建下的 `deepseek-v4-flash` 会话行为不变。

## Consequences

在哨兵行处结束的流变为可用，这正是受影响的网关路由得以可用的前提。本次改动不附带任何配置：宽松路径是关于哨兵的事实而非关于某个部署的事实，因此无需额外知晓或设置什么。

截断防护恰好收窄了一种情形，且该情形不可能掩盖数据丢失。原本单一的判定条件——已分派的 `[DONE]`——如今成为通向同一结论的两条路径，因此本模块承担了少量此前完全属于解析器的分帧知识（`EVENT_TERMINATORS`）。这部分知识仅用于测量尾部片段；事件分帧本身仍归 `eventsource-parser` 所有。
