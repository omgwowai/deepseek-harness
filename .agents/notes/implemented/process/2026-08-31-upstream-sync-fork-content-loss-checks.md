# Agent Note: Prove zero fork-content loss when syncing upstream

Status: implemented

English | [中文](2026-08-31-upstream-sync-fork-content-loss-checks.zh.md)

## Problem

Syncing 0.1.1-rc.2 to 0.1.2-alpha.2 moved 1313 upstream commits across 6868 files. The [previous sync's rule](2026-08-24-upstream-sync-regenerates-generated-conflicts.md) — resolve generated conflicts by taking upstream's side and rerunning the generator, then diff the merged catalogs against the upstream tag to prove zero *upstream* removals — held. What it does not cover is the other direction: a regenerated artifact whose English side is generator output and whose Chinese side is a hand-maintained reviewed counterpart. Rerunning the generator rewrites only the English file, so upstream's side of the conflict silently wins on the Chinese one and the fork's own sections disappear.

That loss is invisible to the catalog gates, because a Chinese file missing a section is internally consistent. It surfaced only as two broken anchors in `verify-md-links`, three steps removed from the cause, and the same class had already cost content in three separate places: the `tokenrouter-rollout` section and the `client-ui-rollout` no-config entry in `docs/config-catalog.zh.md`, the fork's `stream` field in that file's `web-search-deepseek` block, and three rows in `docs/event-producer-consumer.zh.md`.

This sync also inherits upstream removals that break the fork by omission rather than by conflict. Upstream deleted `packages/client/runtime` and `packages/host/apiproxy`, and a fork-only `tsconfig.json` still referenced the first by relative path.

## Decision

Every bilingual pair the merge touches is compared structurally, not read for plausibility. For a pair whose English side is generated, the Chinese side is diffed against it on the extracted invariants both sides must share: anchor list, heading list, fenced-code-block bodies, `../`-relative link targets, and table row keys. All of those are language-independent by construction, so any difference is either an intended localization (a `.zh.md` link target, a translated table header) or content loss. Only after that comparison is clean does the pairing record get re-recorded — re-recording first would stamp the loss as a confirmed-consistent state, which is exactly what the record is supposed to rule out.

A dangling TypeScript project reference is found by searching the reference syntax, not the deleted path. `scripts/clean.ts` walks the root reference graph and calls `parseConfig()` on every `projectReferences` entry, which throws on the first unreadable one, so a single stale relative `"path"` aborts the whole clean with an error naming the missing file and not the file that names it. `packages/client/ui-rollout/tsconfig.json` held `{ "path": "../runtime" }`; a grep for `client/runtime` cannot find it and a grep for `\.\./runtime` finds it immediately.

Upstream's two new gates are treated as gates on fork content, not as upstream's business. `verify-client-ui-i18n` rejects hard-coded UI copy in Client source, and the fork's `RolloutButton` carried a literal `Rollout` label plus a literal failure label with a comment claiming failure copy is exempt. It is not: the button now renders `button.label`, the already-declared but unused `button.running`, and a new `button.error`, while the provider's failure detail stays verbatim in `title` because that string is a diagnostic and not copy. `doc-standard.spec.ts` requires a `description`/`kind` frontmatter and a `Summary`/`Table of Contents`/`Dev Note` skeleton on every package README, so all four fork READMEs are restructured onto it; two stale facts in `ui-rollout`'s were corrected in the same pass, the details-footer seat now being declared by `client-ui-chat` and the settings namespace registered through `settings.installSection`.

`publint` and `verify-built-package-invariants` consume built `lib/`. Both fail on a clean tree and fail identically on pristine upstream, so a `hygiene` run after `clean` proves nothing about either until `build` has run. That ordering is a property of the artifact plane, not a fork defect.

## Alternatives considered

**Read the merged Chinese files and judge whether anything is missing.** 3600 lines of catalog across 117 sections is exactly the input human review is worst at. The extracted-invariant diff is mechanical, finds all four losses at once, and its output is a list of positions rather than a claim of having looked.

**Regenerate the Chinese catalog too.** No generator produces it. The header comment says the English side is generated by `scripts/gen-config-catalog.ts` while the Chinese side is a reviewed counterpart maintained through bilingual pairing, and that is the design: a generated translation would be a translation nobody reviewed.

**Take the fork's side for the conflicting Chinese files.** It keeps the fork's sections and drops upstream's, trading one direction of silent loss for the other. Taking upstream's side and restoring the fork's sections from the pre-merge blob is the only resolution where both survive.

**Localize the rollout button's failure label as `title` only and leave the visible text English.** The visible span *is* the label; leaving it English makes the gate correct and the UI inconsistent with every other localized surface. The distinction that survives is between copy the surface chooses (localized) and detail the provider returns (verbatim).

**Re-record the pairing records first and fix content afterwards.** The record's whole meaning is that the two sides were confirmed consistent at that hash. Recording a known-lossy state and repairing later leaves a window in which the gate actively asserts something false.

## Consequences

- `doc-sync` passes 32/32 and `hygiene` 15/15 after a build. `typecheck` and `lint` are clean, and `verify-md-links` resolves all cross-links across 2209 files.
- The structural-invariant comparison is the check that would have caught the previous sync's version of this problem too, and it is cheap enough to run on every pair a merge touches. It does not generalize to prose-only pairs, where a dropped paragraph shares no extractable invariant with its counterpart; those still depend on the pairing record plus review.
- Restoring the fork's `docs/config-catalog.zh.md` section by hand means the Chinese catalog now carries a section whose label convention had to be chosen deliberately: the pre-merge fork section used `依赖：` while upstream's 95 other sections use `需要：` for the same English `Requires:`. The restored section follows upstream.
- `verify-client-ui-i18n` closes the class of defect where a fork surface reads correctly in English and untranslated everywhere else. It cannot check that a locale value is a correct translation, only that copy is locale-owned.
- Two upstream package deletions leave the fork responsible for references upstream cannot see. A fork-only `tsconfig.json` is not covered by any upstream gate, so the same failure recurs on the next sync that deletes a package the fork references — detectable in one command (`grep -rn '\.\./<name>' --include='tsconfig*.json'`) once the deletion is known.
